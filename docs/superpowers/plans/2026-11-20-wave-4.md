# Wave 4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add Bluesky, SoundCloud, Apple Music, Apple Podcasts, Tumblr, Kick and Giphy to `social-embeds`, released together as 0.5.0.

**Architecture:** Each platform gets a parser module in `src/parser/platforms/`, a component in `src/components/`, a route in `<SocialEmbed>`, playground samples and README rows, following wave 3 (commits `85b608a`…`db9e95c`). Five platforms are iframes on `IframeEmbed`. Bluesky and Tumblr use either the script path (`ScriptEmbed` + a `Driver`, as Pinterest) or the iframe path with height from the frame (`IframeEmbed` + `MessageHeight`, as Reddit), decided in Task 1.

**Tech Stack:** TypeScript, React 19, Vitest + Testing Library, pnpm 12, Next.js 16 playground, Changesets.

**Spec:** [docs/wave-4-brief.md](../../wave-4-brief.md). Read it with [docs/project-brief.md](../../project-brief.md) and `docs/decisions.md` (D14, D28, D35, D39, D52, D53, D56, D57, D60, D61, D64, D68 are referenced throughout).

## Global Constraints

- The package makes no network calls (project brief §2). No handle, token or redirect lookups.
- Strict input (D14): embed code is one platform's own markup. The only new extras are SoundCloud's attribution `div`, Giphy's `<p>` credit and Giphy's responsive wrapper `div`, each matched exactly and dropped.
- `verifyEmbed` requires `matchUrl(embed.url).url === embed.url` (D57): every canonical URL a parser writes must round-trip through `matchUrl`.
- Options never replace verified content (D68): `url`, `video`, `i`, `id`-like keys are content, never options.
- Iframes are created on the client only (D28).
- A SoundCloud URL renders `visual=true` at 400 px (maintainer, 2026-11-20). Embed code keeps its own layout and height.
- A Bluesky URL renders only when its profile part is a DID. A handle URL, and a Tumblr URL if Task 1 finds no URL form, render nothing; `onError` gets exactly `social-embeds: a {Name} URL needs a lookup: use the embed code`.
- The "needs a lookup" check is internal: `social-embeds/parser` gains no exports.
- New `Platform` values, exactly: `'bluesky' | 'soundcloud' | 'applemusic' | 'applepodcasts' | 'tumblr' | 'kick' | 'giphy'`. Display names: `Bluesky`, `SoundCloud`, `Apple Music`, `Apple Podcasts`, `Tumblr`, `Kick`, `Giphy`.
- `ParsedEmbed['variant']` stays `'sdk' | 'iframe'`.
- Decisions continue at D70 in `docs/decisions.md`. Comments follow the house style: one-line gotchas, TSDoc for what the signature cannot say.
- Commit messages: Conventional Commits, no AI attribution line.
- Every task ends with `pnpm test`, `pnpm lint`, `pnpm typecheck` green.

## Review Focus

1. A Bluesky handle URL passed to `<SocialEmbed url>` or `BlueskyEmbed url`: nothing renders and `onError` names the lookup, not "not a supported post URL". Test in Task 7 and Task 8.
2. A host-built embed whose `options` carry a content key (`url` for SoundCloud, `i` for Apple, `video` for Kick): the iframe `src` keeps the verified content. Test in Task 5 and Task 6.
3. A private SoundCloud track (`secret_token`) parsed from embed code survives `verifyEmbed` and reaches the `src`. Test in Task 2 and Task 5.
4. Giphy or SoundCloud embed code with the platform's extra plus anything else (a second link, a foreign script, another element): `parseEmbed` returns `null`. Test in Task 2 and Task 3.
5. Apple embed code carrying its own `sandbox`/`allow`: the iframe gets the component's constants, never the input's. Test in Task 5.
